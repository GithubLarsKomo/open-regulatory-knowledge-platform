# TASK: Reduce Relation Validation Roundtrips

## Objective

Reduce the successful `RegulatoryObjectRepository.create_relation()` path from **5 SQL statements to <=2**, including the relation `INSERT`, without changing relation validation or transaction semantics.

> Repository note: root `TASK.md` is generated by `tools/backlog_generator.py`. This performance task therefore lives under `PERFORMANCE/TASK.md` to avoid corrupting the canonical generated backlog artifact.

## Baseline

- Python 3.10: median 1.694 ms; exactly 5 SQL statements/sample.
- Python 3.12: median 1.359 ms; exactly 5 SQL statements/sample.
- Baseline harness: `tools/performance_write_baseline.py`.

## Root cause

The method performs four independent validation reads before adding the relation:

- source version;
- target version;
- source object;
- target object.

## Implementation

- [ ] Replace the four point reads with one joined endpoint-context query.
- [ ] Preserve source-version then target-version error precedence.
- [ ] Preserve canonical relation-type validation.
- [ ] Preserve `validate_relation(source_type, relation_type, target_type)` behavior.
- [ ] Correctly handle source == target and/or identical version pair.
- [ ] Do not add caching, new infrastructure, schema changes or commits inside the repository method.

## Functional gate

- [ ] Existing relation tests pass unchanged.
- [ ] Missing source version still raises `InvalidRelationError` with source context.
- [ ] Missing target version still raises `InvalidRelationError` with target context.
- [ ] Invalid relation type still raises the canonical error.
- [ ] Incompatible endpoint types are still rejected by relation policy.
- [ ] Full pytest suite passes on Python 3.10 and 3.12.

## Performance gate

- [ ] `repository_create_relation`: <=2 SQL statements/sample after `flush()`.
- [ ] `repository_create_object`: remains 3 SQL statements/sample.
- [ ] Existing read/list baseline scenarios remain 1 SQL statement/sample.
- [ ] Record Before/After timing but do not use hosted-runner milliseconds as a hard gate.

## Verification

Run:

```bash
python -m pytest -q
python tools/performance_baseline.py
python tools/performance_write_baseline.py
```

CI must pass both Python matrix jobs and upload baseline artifacts.

## Definition of Done

The implementation is complete when functional behavior is unchanged, valid relation creation requires no more than two SQL statements including the insert, the full CI matrix is green, and no additional complexity remains after a simplification review.
